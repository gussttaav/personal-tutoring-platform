      import json
      from pyodide.http import open_url
      exec(open_url("/courses/llm-agents/guionizado.py").read())   # ModeloGuionizado, para ensayar

      SISTEMA = ("Respondes preguntas sobre la novela Marianela sólo con los pasajes numerados que "
                 "acompañan a cada una. Responde sólo con un objeto JSON de dos campos: «respuesta», "
                 "lo más breve posible, y «pasaje», el número del pasaje donde la has leído. Si "
                 'ninguno la responde: {"respuesta": "no lo sé", "pasaje": null}')

      def montar(pregunta, pasajes):
          """El prompt de sistema y un mensaje del usuario: los pasajes numerados y la pregunta."""
          texto = "".join("[%d] %s\n" % (i + 1, p) for i, p in enumerate(pasajes))
          return [("sistema", SISTEMA), ("usuario", texto + "Pregunta: " + pregunta)]

      def cumple(y, m):
          """La comprobación: el objeto leído si la respuesta y tiene la forma, None si no."""
          try:
              r = json.loads(y)
          except ValueError:
              return None
          if not isinstance(r, dict) or set(r) != {"respuesta", "pasaje"}:
              return None
          texto, n = r["respuesta"], r["pasaje"]
          if not isinstance(texto, str) or not texto:
              return None
          if n is None:
              return r if texto == "no lo sé" else None
          if type(n) is not int or not 1 <= n <= m or texto == "no lo sé":
              return None
          return r

      def asistente(modelo, pregunta, pasajes, tope=2):
          """La primera respuesta que cumple, con el pasaje citado; como mucho tope llamadas."""
          if not pasajes:
              return "no lo sé", None                     # nada que leer: no hace falta llamar
          mensajes = montar(pregunta, pasajes)
          for _ in range(tope):
              r = cumple(modelo(mensajes), len(pasajes))
              if r is not None:
                  n = r["pasaje"]
                  return r["respuesta"], None if n is None else pasajes[n - 1]
          raise ValueError("ninguna de las %d respuestas cumple la especificación" % tope)
    explanation: 'El bucle es corto; lo que importa es lo que garantiza. Ninguna salida del asistente esquiva `cumple`: o devuelve una respuesta que la ha pasado, o el «no lo sé» que escribe el propio harness, o lanza. Sale del bucle en la primera que cumple, así que nunca gasta una llamada de más, y el `for` le pone el tope. Y cada prueba de las de arriba es una conversación guionizada: el modelo guionizado falla si tus mensajes no son los que esperaba y `modelo.turno` cuenta tus llamadas, así que el contrato se comprueba cláusula a cláusula, sin ningún modelo de verdad. Eso es lo que compra que el modelo sea un guion.'

<Leccion slug="evaluar">La lección sobre evaluar</Leccion> dejó un banco de pruebas y un intervalo,
pero lo que midió fueron respuestas escritas una a una, sin recuperador delante ni comprobación
detrás. Ese harness no existía. Sus piezas sí: el recuperador de TF-IDF (*term frequency–inverse
document frequency*), la especificación con su comprobación, la ventana con su presupuesto. Cada
una salió de su lección con un contrato propio, y ninguno dice qué pasa cuando la salida de una es
la entrada de otra: qué hace la comprobación con un pasaje citado que no estaba en el *prompt*, o
qué hace el *harness* si el recuperador no trae nada.

Y cuando el asistente entero falla una prueba, el número baja sin decir de quién es el fallo. Si el
pasaje no llegó, ningún modelo mejor lo arregla. Si llegó y el modelo lo leyó mal, ningún
recuperador mejor. ¿Qué tiene que prometer un asistente que recupera, responde en un formato y se
mide, y cómo se reparte entre sus piezas lo que falla?

Sigue una pregunta por el asistente que construye esta lección: <W>¿Quién toca el piano?</W> El
recuperador trae tres pasajes de *Marianela*. El primero, <W>Quién sabe, quién sabe, amigo
mío....</W>, sólo comparte con ella <W>quién</W>, pero lo repite. El segundo es <W>—Es la señorita
Sofía, que toca—afirmó María.</W>, y el tercero, <W>Calló el piano, como un ave cantora…</W> El
harness los numera, los pone delante de la pregunta, bajo un prompt de sistema que pide un objeto
JSON (*JavaScript Object Notation*) con la respuesta y el número del pasaje donde la ha leído, y
llama al modelo. Vuelve <W>\{"respuesta": "María", "pasaje": 2\}</W>.

La comprobación lo lee: es JSON, tiene los dos campos y el 2 es uno de los pasajes que había.
Cumple, y el harness lo devuelve con el texto del pasaje 2 al lado. El evaluador lo compara con la
respuesta esperada, <W>Sofía</W>, y es un fallo. Mira de quién. El pasaje llegó, la forma era la
pedida y lo citado dice la respuesta correcta: falló la lectura, porque <W>afirmó María</W> no
dice quién toca. La cita es lo que deja verlo sin abrir la novela.

<Callout type="intuition" title="La idea en una frase">
Un asistente es una cadena de piezas con contrato, y cada fallo es de la primera que falla. La
cita hace que la respuesta se pueda revisar, el reintento arregla los fallos de azar y no los de
costumbre, y medir etapa por etapa dice qué pieza mejorar, mientras el recuperador pone el techo a
todo lo demás.
</Callout>

## El contrato del asistente

La firma es `asistente(modelo, pregunta, k=3, tope=2) -> (respuesta, citado)`, y el contrato, por
orden:

1. Recupera con TF-IDF como mucho $k$ pasajes de coseno positivo con la pregunta, del mejor al
   peor. Si no hay ninguno, devuelve <W>no lo sé</W> sin llamar al modelo: no hay nada que leer, y
   decir que no lo sabe no necesita al modelo.
2. Monta una llamada: el prompt de sistema con la especificación y un mensaje del usuario con los
   pasajes, numerados desde 1, y la pregunta al final. Si no cabe en la ventana, descarta pasajes
   del peor, con la regla de `encajar`.
3. Llama al modelo con esos mensajes, como mucho $\text{tope}$ veces, y se queda con la primera
   respuesta que cumple: un objeto JSON con exactamente dos campos, `respuesta`, un texto no vacío,
   y `pasaje`, un entero entre 1 y el número de pasajes, o `null` si, y sólo si, la respuesta es
   <W>no lo sé</W>.
4. Devuelve la respuesta y el texto del pasaje citado. Si ninguna llamada cumple, lanza un error.

Los invariantes salen de ahí. Lo que devuelve ha pasado siempre la comprobación, o lo ha escrito el
harness. Nunca hace más de $\text{tope}$ llamadas. Y el pasaje citado es uno que el modelo tenía
delante, así que cualquiera puede ir a mirar si dice lo que la respuesta dice. Lo que el contrato no
promete es que lo diga: una cita válida puede respaldar una respuesta falsa, y eso lo decide el
evaluador.

La cláusula 3 pide la forma al modelo y la comprueba después. Con un modelo cuyos logits controlas,
la máscara de <Leccion slug="salida-estructurada">la lección sobre la salida estructurada</Leccion>
la garantizaría en cada respuesta. El modelo guionizado devuelve texto, como uno servido por otros,
y lo que le queda al harness es comprobar y volver a llamar.

### Reintentar compra contra el azar

**Reintentar** es volver a llamar al modelo con los mismos mensajes cuando su respuesta no cumple.
Escribamos $\pi_\theta(\text{cumple} \mid s, x)$ para la probabilidad de cumplir de una llamada,
como en <Leccion slug="el-prompt-es-una-especificacion">la lección sobre la especificación</Leccion>,
sin ejemplos y con $x$ el mensaje del usuario, pasajes y pregunta juntos. Si cada llamada es un
sorteo aparte, las $\text{tope}$ llamadas fallan todas con probabilidad

$$
\bigl(1 - \pi_\theta(\text{cumple} \mid s, x)\bigr)^{\text{tope}}.
$$

Es el muestreo por rechazo de la lección sobre la salida estructurada, con la comprobación en el
lugar de la gramática y un máximo de intentos. Hereda su virtud: la respuesta aceptada es un sorteo
de la distribución condicionada a cumplir, sin la deformación de la máscara. Y hereda su coste, que
el tope corta. La llamada $i$ se hace sólo si fallaron las $i - 1$ anteriores, así que

$$
\mathbb{E}[\text{llamadas}] = \sum_{i=1}^{\text{tope}} \bigl(1 - \pi_\theta(\text{cumple} \mid s, x)\bigr)^{i-1} = \frac{1 - \bigl(1 - \pi_\theta(\text{cumple} \mid s, x)\bigr)^{\text{tope}}}{\pi_\theta(\text{cumple} \mid s, x)},
$$

la serie geométrica de aquella lección, cortada en $\text{tope}$ términos. A un modelo que cumple 9
veces de cada 10, un tope de dos le deja sin respuesta una pregunta de cada cien, por 1.1 llamadas
de media. Al mini-GPT, que escribía un JSON válido con probabilidad $8.1 \times 10^{-63}$, ningún
tope lo salva.

La cuenta es de una pregunta. Sobre todas las que recibe el harness, la probabilidad de cumplir
cambia de una a otra, y la fracción que se queda sin respuesta es la media de las probabilidades de
fallar todas. Elevar a $\text{tope}$ es convexo en $[0, 1]$, y la desigualdad de Jensen de
<Leccion slug="plantilla-de-chat">la lección sobre la plantilla</Leccion> da

$$
\mathbb{E}_x\Bigl[\bigl(1 - \pi_\theta(\text{cumple} \mid s, x)\bigr)^{\text{tope}}\Bigr] \ge \Bigl(1 - \mathbb{E}_x\bigl[\pi_\theta(\text{cumple} \mid s, x)\bigr]\Bigr)^{\text{tope}},
$$

donde $\mathbb{E}_x$ es la media sobre las preguntas, con igualdad sólo si todas cumplen con la
misma probabilidad. Lo que reintentar promete con la media es una cota optimista. Si un modelo
cumple el 90 % de las veces porque falla un poco en todas, un tope de dos deja un 1 % sin
respuesta; si es porque un 10 % de las preguntas lo hacen fallar siempre, deja ese 10 % con
cualquier tope. Con temperatura 0 todas son del segundo tipo: los mismos mensajes dan la misma
respuesta. Reintentar arregla los fallos de azar, no los de costumbre.

## Medir etapa por etapa

El evaluador de la lección anterior da un 1 o un 0 por prueba. Para repartir los fallos, el banco
tiene que saber una cosa más de cada prueba: qué pasaje la responde. Con eso, cada prueba pasa por
tres etapas en orden. ¿Llegó el pasaje entre los $k$? Se sabe sin llamar al modelo. ¿Cumplió la
respuesta? Lo dice la comprobación. ¿Acertó? Lo dice el evaluador. Un fallo es de la primera etapa
que falla: del recuperador, del formato o de la lectura.

Llamemos $\text{recuperadas}$ a la fracción de pruebas cuyo pasaje llegó, y
$\text{acierto}_{\text{rec}}$ y $\text{acierto}_{\text{no rec}}$ a la tasa de acierto
(*accuracy*) dentro de cada grupo. Contando las mismas pruebas de dos maneras,

$$
\text{acierto} = \text{recuperadas} \cdot \text{acierto}_{\text{rec}} + (1 - \text{recuperadas}) \cdot \text{acierto}_{\text{no rec}},
$$

que es la probabilidad total de <Leccion slug="recuperacion">la lección sobre recuperación</Leccion>
con las fracciones del banco en lugar de las probabilidades. Aquí no aproxima nada, es una
identidad. La especificación le prohíbe al modelo responder sin pasaje: tiene que decir <W>no lo
sé</W>, que no acierta ninguna prueba con respuesta. Si la obedece,
$\text{acierto}_{\text{no rec}} = 0$, y

$$
\text{acierto} = \text{recuperadas} \cdot \text{acierto}_{\text{rec}} \le \text{recuperadas}.
$$

El recuperador pone el techo. Un modelo que lea sin fallar lleva el acierto hasta
$\text{recuperadas}$ y no más, igual que en la lección sobre la especificación un prompt perfecto
no pasaba de lo que el modelo sabía hacer.

Dos cuidados. Cada fracción se mide sobre su grupo, no sobre el banco: $\text{acierto}_{\text{rec}}$
sale de las pruebas recuperadas, y su intervalo de Wilson es el de ese $n$, más pequeño. Cuantas
más etapas separas, menos pruebas le quedan a cada una. Y dos fallos del recuperador valen 0 los
dos aunque no se parezcan: <W>no lo sé</W> es la especificación cumplida, y un nombre inventado
con un pasaje citado que no lo dice es justo lo que el harness quería evitar. La cita permite
contarlos aparte.

    v = np.zeros(len(COL))

            v[COL[w]] = n * math.log(len(PASAJES) / DF[w])

    """Los textos de, como mucho, k pasajes de coseno mayor que minimo, del mejor al peor."""
    q = tfidf(pregunta)

    cos = np.divide(D @ q, normas, out=np.zeros(len(D)), where=normas > 0)
    return [PASAJES[i] for i in np.argsort(-cos, kind="stable")[:k] if cos[i] > minimo]

def montar(pregunta, pasajes):
    """El prompt de sistema y un mensaje del usuario: los pasajes numerados y la pregunta."""
    texto = "".join("[%d] %s\\n" % (i + 1, p) for i, p in enumerate(pasajes))

def cumple(y, m):
    """La comprobación: el objeto leído si la respuesta y tiene la forma, None si no."""
    try:
        r = json.loads(y)
    except ValueError:                                    # no es JSON, o sobra texto
        return None
    if not isinstance(r, dict) or set(r) != {"respuesta", "pasaje"}:
        return None

    if not isinstance(texto, str) or not texto:
