      import numpy as np


      def gru_step(h, x, P):
          def pre(k, state):
              Wx, Wh, b = P[k]
              return Wx @ x + Wh @ state + b

          def sigmoid(z):
              return 1.0 / (1.0 + np.exp(-z))

          z = sigmoid(pre("z", h))
          r = sigmoid(pre("r", h))
          cand = np.tanh(pre("h", r * h))
          return (1 - z) * h + z * cand

So far the block has moved forward by asking what each network lacks: the vanilla recurrent neural
network (RNN) lacked a memory that could survive distance, and the long short-term memory (LSTM) of
the previous lesson, on gated memory, supplied one. But it came at a cost: four times the weights of
a vanilla RNN, and a second vector hauled through every step. And the lesson itself closed by
doubting that it needed every one of its gates. When an architecture works, the question left isn't
what it lacks, but what it could do without.

Simplifying for real isn't removing pieces until something breaks, but removing them without losing
what they bought. And what the LSTM bought (the one thing that justified all the apparatus) was the
path along which the gradient comes back intact across many steps. Any cut has to be checked against
it: if merging gates or deleting states loses that path, the simplification has thrown away exactly
what mattered. The gated recurrent unit (GRU) is the cut that passes the test, and that's why it
became the LSTM's standard alternative in practice: a quarter fewer weights than the LSTM, one state,
and (almost always, not always) the same result.

The cut fits in two ideas. The first fuses the forget gate and the input gate: instead of
deciding separately how much is kept and how much is written, the GRU uses a single control (the
**update gate**) that says how much to replace, and what it doesn't replace is what it keeps. The
state stops being a sum that can grow without a brake and becomes a mix, a point partway between what
was there and what is proposed for writing; and a mix of bounded things stays bounded, so the output
gate that trimmed the state in the LSTM before showing it is no longer needed.

The second idea is a small new gate, the **reset gate**, which leaves the memory alone and acts on
the candidate instead: it lets the candidate ignore the previous state when what has to be written now
carries nothing over from before (at the start of a new sentence, for example). With those two, and
with a single state that serves as memory and output at once, the second vector disappears: there is
no longer a cell state hidden behind the one that is shown.

Before the formulas, go back for a moment to the LSTM the GRU simplifies. Step through it and watch
the first two rows (the forget gate and the input gate) move separately: those are the two the GRU is
going to tie into one.

## Keeping and writing with a single gate

Start with the line that changes everything. The LSTM's cell added two terms with independent gates,
$\mathbf{c}_t = \mathbf{f}_t \odot \mathbf{c}_{t-1} + \mathbf{i}_t \odot \tilde{\mathbf{c}}_t$; the
GRU works directly on the hidden state $\mathbf{h}_t \in \mathbb{R}^{d_h}$ (there is no second
vector) and ties the two gates into one:

$$
\mathbf{h}_t = (1 - \mathbf{z}_t) \odot \mathbf{h}_{t-1} + \mathbf{z}_t \odot \tilde{\mathbf{h}}_t,
$$

with $\mathbf{z}_t \in (0,1)^{d_h}$ the update gate and $\tilde{\mathbf{h}}_t \in (-1,1)^{d_h}$ the
candidate, the state the step proposes. Coordinate by coordinate it is a weighted average of the old
and the new: $z_{t,j} = 0$ leaves $h_{t,j}$ equal to $h_{t-1,j}$ (it keeps) and $z_{t,j} = 1$ replaces
it entirely with the candidate (it writes). There is no way to do both at once, and that is exactly
the freedom the LSTM had and the GRU gives up: there, $\mathbf{f}_t$ and $\mathbf{i}_t$ could both
open and accumulate. In exchange, an average of bounded numbers doesn't overflow, and that's why the
GRU shows the state as it is, without the output gate or the $\tanh$ that trimmed it in the LSTM
before letting it out.

The update gate is computed like every gate in the previous lesson, a sigmoid layer over the token
and the previous state:

$$
\mathbf{z}_t = \sigma\left(\mathbf{W}_{xz}\mathbf{x}_t + \mathbf{W}_{hz}\mathbf{h}_{t-1} + \mathbf{b}_z\right),
$$

with $\mathbf{W}_{xz} \in \mathbb{R}^{d_h \times d_{\text{model}}}$,
$\mathbf{W}_{hz} \in \mathbb{R}^{d_h \times d_h}$ and $\mathbf{b}_z \in \mathbb{R}^{d_h}$: the same
shapes as the recurrence in <Leccion slug="la-rnn-vanilla">the lesson on the vanilla RNN</Leccion>.

That leaves the candidate, and this is where the second gate comes in. In the LSTM the candidate
always read the whole previous state; the GRU puts a filter in front of it, the reset gate
$\mathbf{r}_t$, which decides how much of that state it gets to read:

$$
\mathbf{r}_t = \sigma\left(\mathbf{W}_{xr}\mathbf{x}_t + \mathbf{W}_{hr}\mathbf{h}_{t-1} + \mathbf{b}_r\right),
\qquad
\tilde{\mathbf{h}}_t = \tanh\left(\mathbf{W}_{xh}\mathbf{x}_t + \mathbf{W}_{hh}\left(\mathbf{r}_t \odot \mathbf{h}_{t-1}\right) + \mathbf{b}_h\right).
$$

The $\mathbf{r}_t \odot \mathbf{h}_{t-1}$ is the only thing that sets this candidate apart from a
vanilla RNN step: with $\mathbf{r}_t = \mathbf{1}$ the candidate is the recurrence from <Leccion slug="la-rnn-vanilla">the lesson on the vanilla RNN</Leccion> as it stands, and with
$\mathbf{r}_t = \mathbf{0}$ it is computed from the token alone, as if the sequence began there.
Keep the two gates apart: $\mathbf{z}_t$ decides whether the state is updated, $\mathbf{r}_t$ decides
what the candidate looks at to make its proposal. One governs the memory; the other, the candidate.

The three pieces together, with $\mathbf{h}_0 = \mathbf{0}$ for the same reason as in the RNN and the
LSTM:

$$
\begin{aligned}
\mathbf{z}_t &= \sigma\left(\mathbf{W}_{xz}\mathbf{x}_t + \mathbf{W}_{hz}\mathbf{h}_{t-1} + \mathbf{b}_z\right), &
\mathbf{r}_t &= \sigma\left(\mathbf{W}_{xr}\mathbf{x}_t + \mathbf{W}_{hr}\mathbf{h}_{t-1} + \mathbf{b}_r\right), \\
\tilde{\mathbf{h}}_t &= \tanh\left(\mathbf{W}_{xh}\mathbf{x}_t + \mathbf{W}_{hh}\left(\mathbf{r}_t \odot \mathbf{h}_{t-1}\right) + \mathbf{b}_h\right), &
\mathbf{h}_t &= (1 - \mathbf{z}_t) \odot \mathbf{h}_{t-1} + \mathbf{z}_t \odot \tilde{\mathbf{h}}_t.
\end{aligned}
$$

Three pieces (two gates and a candidate), each with exactly the shape of the recurrence in <Leccion slug="la-rnn-vanilla">the lesson on the vanilla RNN</Leccion>: six matrices and three biases, $3\left(d_h \cdot d_h + d_h \cdot d_{\text{model}} + d_h\right)$
weights. Against the LSTM's four groups, three quarters; and as there, $T$ appears in none of the
shapes, so the GRU reads any length with the same set of weights.

## Why the return path survives the cut

The whole lesson hangs on one check: that the path along which the gradient comes back (the one the
LSTM bought, and whose need <Leccion slug="gradiente-desvanecido">the lesson on the vanishing gradient</Leccion> explained) is still standing
with one state instead of two. Look at the last line coordinate by coordinate, which is where what the
$\odot$ means becomes visible:

$$
h_{t,j} = (1 - z_{t,j})\,h_{t-1,j} + z_{t,j}\,\tilde{h}_{t,j}.
$$

Along this path, coordinate $j$ of the new state depends on coordinate $j$ of the old one and on no
other: there is no matrix to mix them. Differentiating along the direct path, and holding the gates
and the candidate still (I'll come back to this),

$$
\frac{\partial h_{t,j}}{\partial h_{t-1,j}} = 1 - z_{t,j},
$$

a number, not a matrix. Chain it backwards to a distant step $k$, the way <Leccion slug="gradiente-desvanecido">the lesson on the vanishing gradient</Leccion>
chained the recurrence, and what arrives along the direct path is a product of those numbers:

$$
\frac{\partial \ell}{\partial h_{k,j}} = \left(\prod_{t=k+1}^{T}\left(1 - z_{t,j}\right)\right)\frac{\partial \ell}{\partial h_{T,j}} + \left(\text{what comes in through the gates}\right).
$$

It is, letter for letter, the LSTM's $\prod f_{t,j}$ with $1 - z_{t,j}$ in place of $f_{t,j}$: the
closed update gate ($z_{t,j} \to 0$) plays the part of the open forget gate. And the same holds as
there ($1 - z_{t,j} = 1$ is reachable and stable, because a saturated sigmoid stays flat at the end),
so a coordinate the network learns not to update multiplies by $1$ for as many steps as needed. Against
the $\left(\gamma\,\sigma_{\max}\right)^{T-k}$ of <Leccion slug="gradiente-desvanecido">the lesson on the vanishing gradient</Leccion>, the base has
stopped being a property of a matrix shared by everything and become a number per coordinate and per
step that the network computes.

<Details summary='See what "holding the gates still" left out'>
$\mathbf{z}_t$, $\mathbf{r}_t$ and $\tilde{\mathbf{h}}_t$ are computed from $\mathbf{h}_{t-1}$, so the
full derivative adds, to the direct path's $1 - z_{t,j}$, the paths that go through the two gates and
through the candidate. Every one of them crosses a $\mathbf{W}_{h\ast}$ and an activation mask, and
they vanish the same way as the ones in <Leccion slug="gradiente-desvanecido">the lesson on the vanishing gradient</Leccion>.

That they vanish breaks nothing, and it is the same reading as in the LSTM. Those paths adjust *how
the decision is made* at each step, and a decision at this step is made with what is nearby; the
gradient that has to arrive from far away is the direct path's, and that one crosses no matrix. The GRU doesn't eliminate the product from <Leccion slug="gradiente-desvanecido">the lesson on the vanishing gradient</Leccion>: it moves it off the long path and leaves it on the short ones.
</Details>

Two concessions close the account, the same as in the LSTM. If the network learns $z_{t,j}$ around
$0.3$, the product sinks as it did in the RNN, only because the network decides so and not because
the architecture imposes it. And explosion is still possible along the paths in the box above, so the
GRU is trained with gradient clipping like everything before it. The additive path doesn't hand out a
guarantee; it makes reachable an option that wasn't reachable before.

## The GRU, step by step, in NumPy

One cell. It transcribes the four-line block and runs it on a short sequence with two different
update-gate biases, to see how much of $\mathbf{h}_1$ reaches $\mathbf{h}_6$ along the direct path.

The weights again come from a generator with a fixed seed and aren't trained, so the gates don't mean
anything yet. What I did set by hand is the bias $\mathbf{b}_z$: remember that keeping is $z \to 0$,
so a negative bias is what pushes the network to remember (the mirror image of the LSTM's positive
$\mathbf{b}_f$). Look at the last line of each block.

            for k, b in [("z", update_bias), ("r", 0.0), ("h", 0.0)]}


def step(P, h, x):
    def pre(k, state):
        Wx, Wh, b = P[k]
        return Wx @ x + Wh @ state + b
    z = sigmoid(pre("z", h))
    r = sigmoid(pre("r", h))
    cand = np.tanh(pre("h", r * h))                # the candidate reads r (*) h_{t-1}
    h = (1 - z) * h + z * cand                     # the additive path, tied
    return h, z, r


for bias in [0.0, -3.0]:
    P = weights(bias)
    h, kept = np.zeros(d_h), []
    print("b_z = %.0f" % bias)
    print("  t      z_t              r_t              h_t")
    for t, x in enumerate(X, 1):
        h, z, r = step(P, h, x)
        kept.append(1 - z)
        print("  %d  %s %s %s" % (t, np.round(z, 2), np.round(r, 2), np.round(h, 2)))
    print("  what survives of h_1 in h_6:", np.round(np.prod(kept[1:], axis=0), 3))

Both gates live in $(0,1)$, and each coordinate gets a value of its own (where two print alike, they
differ past the second decimal). Compare the two blocks by their last line. With $\mathbf{b}_z = 0$
the update gate hovers around $0.5$, half the state is replaced at every step, and about $3\%$ of
$\mathbf{h}_1$ reaches $\mathbf{h}_6$; with
$\mathbf{b}_z = -3$ it hovers around $0.05$, almost nothing is updated, and $77\%$ survives, with the
same weights and the same sequence. Hence the habit of initialising $\mathbf{b}_z$ negative, for the
same reason as a positive $\mathbf{b}_f$ in the LSTM: it's cheaper for the network to learn to write
than to learn to remember. And notice the price of the shortcut: with $\mathbf{b}_z = -3$ the state
barely moves ($\mathbf{h}_t$ stays in the hundredths), because keeping and writing are the same
control, and asking it to keep is asking it to barely write.
